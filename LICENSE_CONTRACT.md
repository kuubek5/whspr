# Ліцензійний контракт із сервісом kuub.win

## Що це
Ключі активації для KuubWave видає також **kuub.win License Service**
(репозиторій `kuubek5/personal-site`, файл `api/app/licensing/kuubwave.py`).
Сервіс генерує ключі побайтово так, як їх очікує код цього продукту.
Тому формат ключа тут — **контракт**: зміна без синхронної зміни сервісу
призведе до того, що сервіс мовчки видаватиме недійсні ключі.

## Що саме є контрактом
- Файл: `licensing.py`
- Функція перевірки: `verify_key(key)`
- Константа публічного ключа: `LICENSE_PUBKEY_HEX`
- Формат ключа: ключ = `b64url(payload) + "." + b64url(sig)` (без `=`-padding); payload — компактний JSON `{"c": customer, "e": "YYYY-MM-DD"}` (`separators=(",",":")`, `sort_keys=True`, кодування `json.dumps` за замовчуванням, ensure_ascii), підпис Ed25519 над байтами payload. license_id у форматі нема (для обліку сервіс бере sha256 ключа).

## Правила
1. Не змінюйте формат, підписувані байти, кодування, назви полів чи `LICENSE_PUBKEY_HEX`
   без оновлення сервісу в тій самій зміні (обидва репозиторії, узгоджено).
2. Ротація ключа = **додати** новий публічний ключ, а старий лишити, доки живуть
   видані ліцензії. Старі ключі активації мають залишатися валідними завжди.
3. Не вставляйте приватні ключі в репозиторій (тільки публічні).

## Як перевірити
```
python -m pytest tests/test_license_contract.py
```
Тест підміняє `LICENSE_PUBKEY_HEX` на публічний **тестовий** ключ і перевіряє, що власна
функція `verify_key(key)` приймає еталонні ключі з `tests/fixtures/license_contract.json`
(видані сервісом) і відхиляє підроблений. Окремої тестової інфраструктури в репозиторії нема: потрібні лише `pytest` і `cryptography` (`pip install pytest cryptography`).
**Якщо тест червоний** — ви порушили контракт: або поверніть формат, або
оновіть сервіс і вектори (див. нижче) і повідомте власника.

## Як перегенерувати вектори
У репозиторії personal-site:
```
cd api && uv run python -m tools.make_contract_vectors
```
Потім скопіюйте `api/tests/fixtures/contract/kuubwave.json` у
`tests/fixtures/license_contract.json` цього репозиторію (без змін).
Вектори підписані публічним тестовим ключем — вони не містять справжніх секретів.

## Майбутнє
Планована онлайн-перевірка (v2) працює за принципом **fail-open**: якщо мережі
нема — застосунок продовжує працювати за офлайн-ліцензією.
